Load test (high volume)

The local site at 127.0.0.1:8000 was pressed with thousands of concurrent requests on public pages (home, blog, contact, careers, about, team, legal, dashboard login). The development server php artisan serve handles one request at a time; production Nginx/PHP-FPM is different.

2,350 requests in total: 2,039 succeeded (86.8%). Completed requests returned HTTP 200 with no server error. The remaining 311 were wait timeouts, not a site crash.

Local-environment note

The 305 burst timeouts are not a code crash

A timeout means the local server did not answer within 25 seconds because php artisan serve handles one request at a time and the rest queue. The 95 requests that finished returned 200. The site did not return HTTP 500.

On real hosting (Nginx/PHP-FPM with several workers) the same 120 visitors would not form that queue. This marketing site does not need a large performance project now. After go-live, run a short check and add cache only if real slowness appears there.

Important technical fixes

Security + technical fix

Liability and security (added in this cycle)

  • Removed dd() from LoginComponent — it would halt the app in production
  • Session fixation fix in LogoutComponent — added invalidate() and regenerateToken()
  • APP_DEBUG disabled — error details are not shown to visitors
  • Rate limiting on API routes (throttle:10,1)
  • Upload throttle in Livewire (60 requests/minute)
  • AuthRedirect middleware now checks the route name instead of a sliced path string
  • Blocked IP cache — 5-minute cache instead of a query on every request
  • Unified error message — does not reveal whether email or password was wrong
  • Password minimum 8 characters — previously 6
  • Sanctum expiration = 1440 minutes (24 hours)
  • SESSION_ENCRYPT=true — session data is encrypted
  • Moved DB queries from render() to mount() — BlogDetailComponent and LegalPageComponent
  • HasTranslatableSlug works with SQLite and MySQL — json_extract instead of JSON_UNQUOTE
  • Removed console.log from dashboard JavaScript
  • HTML fixes — sidebar, mobile menu buttons, aria attributes

Fixed in this cycle

Updated

Arabic locale removed — site is English only

Arabic is no longer a supported language. Locale config is English only, Arabic translation files were removed, and /ar redirects to the English site. This report was rewritten in English and older Arabic UI screenshots were retired.

Fixed

Forgot password in the dashboard

The link was decorative and opened nothing. It now opens an email form, sends a reset link, and has a page to set a new password. Sending uses the mail settings stored in the dashboard (not only the server file).

Fixed

Mail sending uses dashboard settings

SMTP settings under Dashboard → Settings → Email are now the source of truth for sending (including SSL for port 465). If the fields are empty, the system does not try a dummy server.

Fixed

Wrong redirect after a “partner” login

Signing in with that role used to open a missing page. It now opens the dashboard home.

Fixed

Admin email mismatch in first-run seed data

Seeding mixed two email formats. The format is now consistent so login details are not confusing at handover.

Fixed

Placeholder contact details hidden

555 numbers, example.com emails, and a Dhaka map no longer show to visitors when contact fields are empty in the dashboard. A “Contact us” link is shown instead. Enter the real phone, email, and address under Settings → Contact when they are available.

Fixed

Job content now matches the listing

Each job description matches its title, location is Remote, and type is full-time. The application form is present and works.
